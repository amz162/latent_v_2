## 1. Daily report — `reports/operations/task127_daily_health.json`

Regenerated by step 5 of the pipeline (extend `task123_daily_pipeline.sh` with `python3 scripts/task127_monitor.py >> "$LOG" 2>&1` after step 5 — recommended operator action; the monitor is also safe to run standalone/cron). Sections:

- **Data pipeline:** OHLCV frontier + bar count, SQLite `quick_check`, last ingest report (frontier, new bars, symbols without provider data), intraday poll-bot heartbeat (last cycle, classification, provider health, consecutive failures), latest pipeline log.
- **Paper trading:** state counts (closed/open/pending_entry), duplicate-fill pair count (must be 0), realized net P&L of the **baseline cohort only**, exit-reason distribution, unrealized MTM note (kept strictly separate from realized).
- **GLM:** store record counts split real/mock, research-only flag, last generation timestamp, scheduled-generation status (honestly `NOT VERIFIED` until Task 124's contract gap is closed).
- **Cohorts:** registry summary, baseline + any forward cohorts reported separately.
- **Metrics policy (binding):** `win_rate` and `profit_factor` are reported **only** for cohorts with closed trades. **Sharpe, Sortino, ROI and max-drawdown are NOT computed or labelled anywhere** — no portfolio equity time series exists in this system (100k-PKR book-level cash, no compounded equity curve), and per the task rules none of these may be labelled without a valid underlying series and documented methodology. The emitted JSON is tested to contain none of these keys.

## 2. Alerts — 10 observable alerts with deduplication and recovery

Engine (`task127_alerts.py`): severity escalation fires immediately (WARN→CRIT bypasses the window); otherwise no re-fire within **12 h** (`suppressed` flag + counter in state); a cleared condition emits a **recovery** event exactly once. All events append to `data/backtest_reports/task127/ops/alerts_log.jsonl`; dedup state lives in `alert_state.json`. Every alert carries **id, severity, timestamp, component, affected record/job, diagnostic reason, suggested operator action**.

| # | id | Trigger (weekday/weekend aware) | Severity | Action field |
|---|---|---|---|---|
| 1 | `heartbeat_stale` | poll-bot heartbeat > 36 h on a weekday (observed cadence ≈ daily) | WARN; CRIT > 72 h | check `intraday-poll.yml` Actions runs + provider health |
| 2 | `eod_ingest_missing` | weekday after 18:00 PKT with no ingest report dated today | WARN | verify S1/S4 executors (task124 operator doc); rerun — idempotent |
| 3 | `missing_psx_sessions` | OHLCV frontier behind the latest completed session | WARN; CRIT ≥ 5 days | run ingest; never backfill from non-provider sources |
| 4 | `provider_repeated_failures` | provider `consecutive_failures ≥ 3` (CRIT ≥ 6) | WARN/CRIT | inspect provider; auto-recovery expected; do not fabricate bars |
| 5 | `lifecycle_not_running` | weekday after 18:30 PKT with lifecycle report > 30 h old | WARN | run the pipeline (idempotent) or install the S4/S1 executor |
| 6 | `pending_entry_accumulation` | pending symbols outside the known provider-gap set {BYCO, ENGRO}, or pending > 40 | WARN | check provider coverage for the new symbols |
| 7 | `duplicate_fill_attempts` | any duplicate (prediction, strategy) parent pair | CRIT | stop lifecycle; restore pre-promotion backup; investigate bookId path |

## 3. Cohort protection

- **Baseline cohort `C20261029`** (start cutoff 2026-10-29, created 2026-10-29T20:21:46Z, 114 records): **frozen**. The monitor partitions trades by creation epoch (baseline = rows created on 2026-10-29) and reports its metrics untouched; tests assert realized net (−707,370.97) and state counts (78/3/33) remain exactly the published Task 125 values on every run. No reset, re-mark, or re-fill of its timestamps/fills; the Task 125 premature-closure classification defect stays documented, not rewritten.
- **Forward cohorts:** any post-freeze trade is grouped into `C<YYYYMMDD>` (explicit start cutoff = its predictions' data-cutoff date), reported **separately** in the registry and daily report, processed idempotently by the (now gate-fixed) lifecycle, and kept in paper mode. Registry CSV: `reports/operations/task127_cohort_registry.csv` — today it carries the baseline row plus the explicit "no forward cohort yet" placeholder.
- **Idempotent processing:** re-running the monitor/lifecycle cannot create duplicate rows (monitor is read-only; lifecycle upserts with append-only legs — task123 suite re-verified in the final gates).

## 4. Forward evaluation metrics

Per cohort, per day: signals generated (predictions total / BUY), valid entries (with risk levels), filled, pending, closed, matured outcomes, realized net P&L, unrealized P&L, trading costs, win rate, profit factor — with win rate/PF only when closed trades exist, and the drawdown prohibition of §1. Baseline snapshot (2026-11-23): 114 records, 78 closed, 3 open, 33 pending, realized −707,370.97 PKR, win rate 12.82%, profit factor 0.0767.
